# CoMPaSS 탭형 워크벤치 및 시각 품질 개선 설계

## 목적

CoMPaSS를 처음 실행한 사용자가 다음 행동을 바로 이해하고, MAPF 실험을 준비·실행·분석·저장할 수 있도록 화면을 목적별 탭으로 재구성한다. 화면 크기에 따른 글자 흐림과 정보 잘림을 줄이고, 지도와 결과 이미지를 읽기 쉽게 표시한다.

## 사용자와 성공 기준

- 주 사용자: MAPF 연구 도구를 처음 접하는 학생·연구자와 반복 실험을 수행하는 사용자.
- 시작 화면에서 예제 선택 → 실행 → 결과 확인의 순서를 설명 없이 이해할 수 있어야 한다.
- 실험 설정, 실행 상태, 결과, 사용법이 각각 분명한 위치에 있어야 한다.
- 작은 해상도에서도 주요 버튼과 상태가 잘리지 않고, 지도는 전체 보기 및 확대가 가능해야 한다.
- 탭 이동 뒤에도 현재 지도, 실행 결과, 리플레이 단계, 로그가 유지되어야 한다.
- 차콜 그레이를 기본으로 밝고 어두운 회색을 구분해 사용하고, 선택·완료·주의·충돌 상태에는 서로 구별되는 절제된 포인트 색을 사용한다. 순수 검정과 파란색 중심 테마를 피하고, 텍스트 대비와 색 외 상태 표식을 함께 제공한다.

## 접근 방식

현재 런타임 UI는 `MapfWorkbenchController` partial 클래스 여러 개에서 생성하는 Unity IMGUI다. 이를 유지해 재작성 위험을 줄이고, 한 페이지에 설정·지도·결과를 모두 넣는 흐름을 탭형 페이지 구성으로 바꾼다. UI Toolkit으로 전면 교체하거나 탭마다 씬을 나누는 방식은 기존 실행 상태와 제어를 다시 연결해야 하므로 이 범위에서는 채택하지 않는다.

## 정보 구조 및 화면 흐름

상단의 고정 탐색 탭은 다음과 같다.

1. **시작·프리셋**: 3개 예제 카드, 각각의 학습 목적, “이 예제로 시작” 동작, 첫 실행 1–2–3 안내. 기존 가이드 모드와 예제 생성 기능을 이곳에 둔다.
2. **실험 설정**: 지도 크기·유형·장애물·시드, 에이전트 수·배치, 알고리즘·탐색 제한, 실시간 미리보기. 기본 설정과 고급 설정을 분리한다. 현재 지도 편집 기능을 유지한다.
3. **실행·리플레이**: 지도 애니메이션, 재생/일시정지/한 단계/속도, 경로·충돌 표시, 선택 에이전트 추적, 판단 및 CBS 시행착오. 실행 중에는 현재 상태와 다음 판단을 눈에 띄게 표시한다.
4. **결과**: 마지막 실행과 연속 실험의 요약, 알고리즘 비교, 사건·복구 로그, 수치 표와 SVG·PNG·CSV·JSON·HTML 내보내기. 내보내기 위치와 저장 완료 피드백을 같은 화면에서 제공한다.
5. **사용법**: 짧은 시작 안내, 맵 범례, 에이전트 선택·지도 조작, 알고리즘 차이, 결과 저장 방법. 용어는 쉬운 설명을 먼저 보여주고 연구 용어는 보조 설명으로 둔다.

탭 탐색은 계속 보이게 둔다. 탭 전환은 뷰만 바꾸며 러너와 실험 상태를 초기화하지 않는다. 실행 중 탭을 바꾸어도 계산과 재생 상태가 유지되고, 실행·리플레이 탭에서 현재 상태로 돌아올 수 있다. 적절한 화면 폭에서는 시작 탭에서 다음 단계로 가는 명시적 버튼을 제공한다.

## 시각 품질과 레이아웃

- 전체 해상도에 단일 `GUI.matrix` 배율을 곱해 글자와 선을 함께 축소하는 방식을 제거하거나 제한한다. 화면 크기와 DPI를 고려해 글꼴·컨트롤 크기를 정하고, 작은 창에서는 열을 접거나 콘텐츠 영역을 스크롤한다.
- 탭 본문마다 독립된 스크롤 상태를 두고, 고정 상단 내비게이션과 핵심 상태가 화면 밖으로 밀려나지 않도록 한다.
- 지도는 남은 화면 공간에 맞춰 표시하고, 전체 지도 맞춤과 확대/축소를 제공한다. 확대 시 격자·장애물·경로·에이전트 ID의 구분이 유지되며 고밀도 지도에서도 조작을 막지 않는다.
- IMGUI의 색상·스타일을 중앙 팔레트로 관리한다. 바탕은 중간 차콜, 카드·입력 표면은 서로 다른 회색, 텍스트는 밝은 회색 계열로 한다. 포인트 색은 따뜻한 앰버와 절제된 녹색·코랄을 의미별로만 사용하며 파란색은 기본 포인트에서 제외한다. 성공·대기·주의·충돌은 색과 아이콘/문구를 함께 사용한다.
- 폰트는 사용 가능한 한글 산세리프 시스템 폰트를 선택하되 대체 폰트를 제공한다. 기본·보조 텍스트 위계를 만들고 축소된 UI에서도 읽을 수 있는 최소 글자 크기를 둔다.
- 화면 캡처는 현재 디스플레이 한계와 무관하게 현재의 고해상도 PNG와 벡터 SVG 내보내기를 계속 제공한다. UI 해상도를 높이는 것과 보고서 그림 해상도는 별도 설정·경로로 설명한다.

## 컴포넌트 경계

- `MapfWorkbenchController`: 현재 실행 상태와 공통 팔레트·스타일, 상단 탭 상태 및 탭 라우팅 소유. 비즈니스 실행 상태는 탭 전환과 독립적으로 보존한다.
- 기존 `MapfWorkbenchGuide`, `MapfWorkbenchResearch`, `MapfWorkbenchExecution`, `MapfWorkbenchReports` partial: 각자 기능에 대응하는 탭 콘텐츠를 그린다. 기능 로직을 중복 구현하지 않고 기존 실행·보고서 메서드를 재사용한다.
- 새 UI 전용 partial이 필요한 경우, 내비게이션과 화면별 레이아웃 책임만 추가한다. 기존 알고리즘과 데이터 모델 변경은 이 설계 범위가 아니다.

## 오류와 경계 조건

- 매우 작은 창에서는 콘텐츠가 겹치지 않게 최소 레이아웃으로 전환하고, 세로 콘텐츠는 스크롤 가능해야 한다.
- DPI 값을 읽을 수 없거나 0인 경우 안전한 기본 배율을 사용한다. 지원하지 않는 폰트가 있으면 대체 글꼴로 표시한다.
- 실행·내보내기 중 탭 이동이 결과나 저장 작업을 취소하거나 중복 생성하지 않게 한다.
- 결과가 아직 없는 상태에서는 결과 탭에 빈 화면 대신 실행 시작 안내를 제공한다.
- 색각 차이에 의존하지 않도록 충돌 종류와 선택 상태에 텍스트/아이콘/선 형태를 병행한다.

## 범위 밖

- UI Toolkit으로 전체 이전, 알고리즘 변경, 새 MAPF 기능 추가, Unity 외부의 웹 대시보드 제작.
- Unity 자체의 시스템 렌더 해상도나 모니터 선명도를 강제로 변경하는 것.

## 확인 기준

1. 다섯 탭을 각각 열 수 있고, 설정·실행·로그·결과가 의도한 탭에서 확인된다.
2. 여러 해상도와 창 크기에서 헤더, 내비게이션, 주요 동작이 겹치거나 잘리지 않는다.
3. 실행 및 리플레이 도중 탭을 이동해도 진행과 현재 단계가 유지된다.
4. 시작 화면에서 예제를 선택하고 결과까지 도달하는 다음 동작이 명확하다.
5. 차콜·회색 테마에서 상태가 읽히고, 파란색 중심 포인트가 남지 않는다.
6. 지도 화면 확대·축소와 기존 SVG·PNG 결과 내보내기가 계속 동작한다.
