# MAPF 기반 길찾기 데이터 처리 최적화 연구 및 시각화 프로그램 개발 명세서

## 0. 프로젝트 개요

### 0.1 개발 목적

본 프로그램은 학교 주제 탐구 프로그램 CoMPaSS에서 진행하는 **대규모 공간 데이터 환경에서의 AI 기반 다중 에이전트 경로 탐색 알고리즘 연구**를 위한 실험 및 시각화 도구이다.

프로그램의 목적은 다음과 같다.

1. 여러 MAPF 알고리즘을 동일한 지도와 조건에서 실행한다.
2. 알고리즘의 경로 생성 과정과 충돌 해결 과정을 시각적으로 확인한다.
3. 실행 결과를 공통 지표로 저장하고 비교한다.
4. 기존 알고리즘의 장점을 조합하거나 새로운 규칙을 추가하여 새로운 데이터 처리 방식을 실험한다.

단순한 경로 탐색 게임이 아니라, **알고리즘의 정확성·효율성·확장성을 검증할 수 있는 연구 플랫폼**을 목표로 한다.

### 0.2 개발 환경

- 게임 엔진: Unity
- 언어: C#
- 화면 구성: 2D 격자 지도
- 기준 개발 기기: Intel Core i5-1240P, RAM 16GB급 노트북
- 전체 개발 기간: 약 43일

처리 성능은 Unity의 화면 출력과 경로 계산 알고리즘을 분리하여 확보한다. 초기 구현은 일반 C#으로 정확성을 우선 검증하고, 실제 측정에서 병목이 확인된 부분에 한해 Unity Job System, Burst Compiler 또는 병렬 처리를 검토한다.

## 1. 연구 범위

### 1.1 기본 문제 정의

프로그램은 정점과 간선으로 구성된 2D 격자 지도에서 여러 에이전트가 각자의 시작점에서 목표점까지 이동하는 고전적 MAPF 문제를 다룬다.

각 에이전트는 한 시간 단계마다 다음 행동 중 하나를 선택한다.

- 위·아래·왼쪽·오른쪽 인접 칸으로 이동
- 현재 칸에서 대기

### 1.2 충돌 정의

- **정점 충돌**: 둘 이상의 에이전트가 같은 시간에 같은 칸을 점유하는 경우
- **간선 충돌**: 두 에이전트가 같은 시간에 동일한 간선을 서로 반대 방향으로 통과하는 경우

유효한 최종 MAPF 해에는 정점 충돌과 간선 충돌이 없어야 한다. 따라서 최종 충돌 수만을 성능 지표로 사용하지 않고, 계획 과정에서 발견된 충돌 수와 실행 중 발생한 충돌을 구분하여 기록한다.

### 1.3 제외 범위

다음 요소는 초기 연구 범위에서 제외한다.

- 실제 로봇의 가속도와 감속
- 회전 반경과 물리 엔진 기반 이동
- 센서 오차와 통신 지연의 실제 물리 모델
- 3차원 경로 탐색

에이전트의 판단은 이산 시간 단계로 계산하되, 화면에서는 시간 단계 사이를 보간하여 부드럽게 이동하도록 표현한다. 이 보간은 시각화 기능이며 알고리즘의 실제 판단 결과를 변경하지 않는다.

## 2. 시스템 설계 원칙

### 2.1 계산과 시각화의 분리

경로 계산 결과를 먼저 시간 단계별 데이터로 생성하고, Unity 화면은 해당 데이터를 재생한다. 대규모 실험에서는 계산과 화면 재생을 동시에 수행하지 않고 계산 완료 후 리플레이하는 방식을 사용할 수 있어야 한다.

### 2.2 알고리즘 모듈화

모든 알고리즘은 동일한 입력과 출력 형식을 사용한다.

#### 공통 입력

- 격자 지도
- 장애물 정보
- 에이전트별 시작점과 목표점
- 최대 계산 시간 또는 탐색 제한
- 난수 시드
- 알고리즘별 설정값

#### 공통 출력

- 에이전트별 시간 단계 경로
- 성공·실패 여부와 실패 원인
- 계산 시간
- 총 이동 비용
- 완료 시간
- 탐색 또는 확장한 노드 수
- 계획 과정에서 발견한 충돌 수
- 대기 횟수 및 재탐색 횟수
- 알고리즘별 추가 로그

새 알고리즘은 공통 인터페이스를 구현하는 방식으로 추가할 수 있어야 한다.

### 2.3 재현 가능한 실험

모든 절차적 생성과 무작위 판단에는 난수 시드를 사용한다. 같은 지도, 에이전트 배치, 시드와 설정을 다시 불러오면 동일한 실험을 재현할 수 있어야 한다.

### 2.4 하드웨어 적응형 실행

사용자가 맵 크기와 에이전트 수를 직접 입력할 수 있도록 하되, 실행 전에 예상 계산 부담을 표시한다. 절대적인 무제한 실행을 보장하지 않고 **사용자 지정 범위에서 현재 하드웨어가 처리할 수 있는 수준까지 확장**하는 것을 목표로 한다.

규모가 커지면 다음 기능을 자동 또는 수동으로 적용한다.

- 선택한 에이전트만 경로 표시
- 개별 로그를 요약 로그로 전환
- 카메라 밖 객체 렌더링 생략
- 이동 애니메이션 표시 빈도 감소
- 계산 완료 후 리플레이 방식으로 전환
- 최대 계산 시간과 메모리 경고 표시

## 3. 주요 기능

### 3.1 지도 생성 및 편집

- 사용자가 지도 너비와 높이를 설정
- 장애물 밀도를 지정하여 절차적으로 지도 생성
- 열린 공간, 무작위 장애물, 좁은 통로, 교차로, 병목 중심 등 실험용 지도 유형 제공
- 지도 칸을 클릭하여 장애물을 직접 추가·제거
- 시작점과 목표점을 자동 또는 수동 배치
- 도달 불가능한 시작점·목표점 배치 검사
- 지도와 배치, 생성 시드를 파일로 저장하고 다시 불러오기

### 3.2 에이전트 관리

- 에이전트 수를 사용자가 설정
- 각 에이전트에 고유 ID, 시작점, 목표점, 상태 부여
- 선택한 에이전트의 경로와 판단 기록을 별도로 표시
- 많은 에이전트가 있을 때 색상만으로 구별하지 않고 ID 또는 선택 강조 기능 제공

### 3.3 시뮬레이션 제어

- 실행, 일시정지, 정지, 재시작
- 한 시간 단계씩 진행
- 재생 속도 조절
- 특정 시간 단계로 이동
- 카메라 이동과 확대·축소
- 경로선, 예약 정보, 충돌 위치, 제약 표시 on/off
- 계산 과정 보기와 최종 경로 재생을 구분

### 3.4 충돌 표시

- 정점 충돌과 간선 충돌을 서로 다른 표시로 구분
- 충돌한 에이전트 ID, 위치 또는 간선, 시간 단계 기록
- 화면이 복잡해지지 않도록 지도에는 핵심 표시만 출력
- 자세한 판단과 충돌 정보는 별도 로그 패널에서 확인

## 4. 구현 대상 알고리즘

### 4.1 A*

A*는 기본적으로 단일 에이전트의 최단 경로를 계산하는 기준 알고리즘으로 구현한다.

- 실제 누적 비용 `g`
- 목표까지의 예상 비용 `h`
- 평가값 `f = g + h`
- 기본 휴리스틱으로 맨해튼 거리 사용
- 허용적 휴리스틱 사용 시 최단 경로 보장

다중 에이전트 실험에서는 각 에이전트의 경로를 독립적으로 계산한 뒤, 충돌이 얼마나 발생하는지 보여주는 기준선으로 활용한다. 모든 에이전트의 위치를 하나의 결합 상태로 탐색하는 Joint A*는 계산량이 매우 크므로 별도의 소규모 비교 기능으로만 검토한다.

### 4.2 Cooperative A*

공간과 시간을 함께 기록하는 예약표를 사용하여 에이전트 경로를 순차적으로 계획한다.

- 정점 예약과 간선 예약 지원
- 대기 행동 지원
- 고정 우선순위와 적응형 우선순위를 선택 가능
- 적응형 판단 기능 on/off
- 우선순위 결정 근거를 점수와 로그로 표시

적응형 우선순위는 외부 생성형 AI가 아니라, 거리·혼잡도·예상 충돌·대기 횟수 등의 값을 이용하는 **설명 가능한 규칙 기반 판단 방식**으로 구현한다. AI 또는 판단 모듈의 실행 비용도 별도로 측정하되, 사용자가 원하면 핵심 경로 비용 비교에서 제외할 수 있도록 한다.

### 4.3 Conflict-Based Search

CBS는 상위 수준의 제약 트리와 하위 수준의 에이전트별 A*로 구성한다.

- 정점·간선 충돌 탐지
- 충돌마다 두 개의 제약 분기 생성
- 제약을 적용한 에이전트의 경로 재탐색
- 제약 트리 노드 비용에 따른 탐색
- 표준 조건에서 완전성과 최적성 검증

결과에는 다음 정보를 포함한다.

- 발견된 충돌 수
- 생성된 제약 수
- 확장한 제약 트리 노드 수
- 재탐색 횟수
- 충돌한 에이전트와 시간·위치
- 최종 경로 비용

### 4.4 CBS 리플레이

CBS의 중간 충돌과 제약 생성 과정을 사용자의 선택에 따라 재생한다.

- 최종 결과만 보기
- 모든 과정을 연속 재생
- 제약 트리 노드를 하나씩 선택하여 보기
- 시간축 이동
- 자유 카메라와 재생 속도 조절
- 충돌 이전과 제약 적용 이후의 경로 비교

ReplayMod의 시간축 탐색과 자유로운 재생 경험을 참고하되, Minecraft의 화면이나 자산을 복제하지 않고 연구용 2D 인터페이스로 구현한다.

### 4.5 개선된 CBS 휴리스틱

DG와 WDG는 학습형 AI가 아니라 CBS 상위 수준 탐색을 안내하는 수학적 휴리스틱으로 구현한다.

- DG on/off
- WDG on/off
- 휴리스틱 비활성화 상태의 기본 CBS와 비교
- 충돌한 에이전트 쌍 표시
- 해당 충돌 관계와 예상 추가 비용 표시
- 휴리스틱 계산 시간과 감소한 탐색 노드 수 기록

DG와 WDG는 CBS의 독립 알고리즘이 아니라 선택 가능한 확장 기능으로 제공한다.

### 4.6 PRIMAL

PRIMAL은 강화학습과 모방학습으로 학습된 공유 정책을 각 에이전트가 국소적으로 실행하는 분산형 MAPF 방식으로 다룬다.

초기 목표는 공개된 학습 완료 모델을 별도의 Python 실행부에서 구동하고, Unity가 입력과 결과를 교환하여 시각화하는 것이다. 공개 구현의 오래된 Python 및 TensorFlow 환경은 Unity 계산 모듈과 분리한다.

- 에이전트별 국소 관측 입력 표시
- 선택한 행동과 판단 결과 기록
- 에이전트별 로그 접기·펼치기
- 성공률과 충돌·교착 위치 기록
- 충돌이 집중된 경로와 구역 표시
- 공개 모델 추론과 자체 규칙 방식 구분

시간이 허용되면 작은 지도와 적은 에이전트 환경에서 직접 학습 또는 재학습 실험을 추가한다. 공개 학습 모델을 실행한 결과와 직접 학습한 결과를 혼동하지 않도록 결과에 모델 출처와 학습 여부를 명시한다.

## 5. 규칙 기반 적응형 판단 모듈

Cooperative A* 등의 사람이 정해야 하는 우선순위를 자동으로 조정하기 위한 중앙 판단 모듈을 제공한다.

판단 요소의 예시는 다음과 같다.

- 목표까지 남은 거리
- 주변 장애물과 에이전트 밀도
- 예상 경로 중첩 수
- 좁은 통로나 교차점 진입 여부
- 누적 대기 시간
- 이전 재계획 횟수

각 판단에는 최종 점수뿐 아니라 요소별 점수와 선택 이유를 기록한다. 사용자는 판단 기능을 끄고 고정 우선순위와 비교할 수 있어야 한다.

이 모듈은 초기에는 머신러닝 모델이나 LLM API를 사용하지 않는다. 이후 연구에서 필요성이 확인될 경우에만 학습형 판단 모델을 별도 실험 기능으로 추가한다.

## 6. 알고리즘 구성 도구

### 6.1 목적

초심자도 소스 코드를 직접 작성하지 않고 여러 판단 규칙을 조합하여 새로운 경로 처리 방식을 시험할 수 있도록 한다.

### 6.2 기본 모드

선택식 인터페이스로 다음 항목을 설정한다.

- 기본 탐색 방식
- 휴리스틱 종류
- 이웃 노드 탐색 순서
- 충돌 시 대기·우회·재탐색 여부
- 에이전트 우선순위 기준
- 동률 처리 방식
- 계산 제한

### 6.3 고급 모드

- 휴리스틱 가중치
- 판단 규칙별 가중치
- 시간 창 크기
- 최대 탐색 노드 수
- 최대 계산 시간
- 무작위성 시드
- 충돌 처리 임계값

설정 결과는 완전한 C# 소스 코드가 아니라 **알고리즘 구성 프로필**로 저장한다. 프로필을 다시 불러와 동일한 실험을 재현하고 기본 알고리즘과 비교할 수 있어야 한다.

게임 안에서 임의 C# 코드를 컴파일하고 실행하는 기능은 보안, 오류 처리와 개발 기간 문제로 초기 범위에서 제외한다.

## 7. 결과 및 로그 시스템

### 7.1 실행 중 화면

- 지도에는 이동과 핵심 충돌 표시만 출력
- 선택한 에이전트의 경로와 상태 강조
- 개별 판단은 로그 패널에 기록
- 에이전트 수가 많으면 로그 요약 모드 사용

### 7.2 알고리즘별 결과 탭

각 알고리즘의 결과를 별도 탭에서 확인한다.

- 실행 조건
- 성공·실패와 원인
- 계산 시간
- 총 이동 비용
- 평균 경로 길이
- 완료 시간
- 탐색 노드 수
- 최대 메모리 사용량
- 계획 과정의 충돌 수
- 재탐색과 대기 횟수
- 알고리즘별 추가 정보

### 7.3 전체 비교 탭

동일한 지도와 에이전트 배치에서 실행한 알고리즘을 한 화면에서 비교한다.

- 수치 표
- 지표별 그래프
- 성공률과 실패 원인
- 시간 대비 경로 품질
- 에이전트 수 증가에 따른 성능 변화
- 장애물 밀도와 병목 정도에 따른 성능 변화

서로 다른 조건에서 측정한 결과를 같은 조건의 직접 비교처럼 표시하지 않는다.

### 7.4 결과 저장

- 실험 설정 저장
- 지도와 에이전트 배치 저장
- 알고리즘 설정 저장
- 원시 실행 결과 저장
- 로그 저장
- 리플레이 저장
- CSV 또는 JSON 내보내기
- 저장한 실험 다시 불러오기

## 8. 실험 설계 지원

프로그램은 다음 독립 변수를 체계적으로 바꾸어 반복 실험할 수 있어야 한다.

- 지도 크기
- 장애물 밀도
- 병목의 수와 폭
- 에이전트 수와 밀도
- 시작점·목표점 분포
- 난수 시드
- 알고리즘과 세부 설정

반복 실험에서는 평균만 제시하지 않고 분산, 표준편차, 최솟값·최댓값, 실패 횟수를 함께 기록할 수 있도록 한다.

주요 종속 변수는 다음과 같다.

- 성공률
- 계산 시간
- 총 이동 비용
- 완료 시간
- 탐색 노드 수
- 메모리 사용량
- 대기 및 재탐색 횟수

## 9. 초심자 중심 UI 원칙

- 처음 실행하면 `지도 설정 → 에이전트 설정 → 알고리즘 선택 → 실행 → 결과 확인` 순서를 안내
- 기본 설정만으로 즉시 예제 실행 가능
- 전문 용어에 짧은 설명과 도움말 제공
- 기본 설정과 고급 설정 분리
- 잘못된 입력은 실행 전에 구체적인 원인과 수정 방법 표시
- 결과 화면에서 수치의 의미와 값이 좋은 방향을 함께 설명
- 화면에 모든 로그를 동시에 표시하지 않고 상세 정보는 탭과 접기 기능으로 제공

## 10. 내부 구조

프로그램은 다음 모듈로 분리한다.

- **Core**: 격자, 좌표, 에이전트, 경로, 시간 단계, 충돌 자료형
- **Algorithms**: A*, Cooperative A*, CBS, DG·WDG, 외부 PRIMAL 연결
- **Simulation**: 계산 결과 실행, 상태 전환, 리플레이
- **Visualization**: 격자와 에이전트 표시, 이동 보간, 경로와 충돌 표시
- **Experiment**: 반복 실험, 성능 측정, 통계 집계
- **Persistence**: 지도·설정·결과·리플레이 저장
- **UI**: 설정 화면, 실행 화면, 로그, 결과 비교

경로 알고리즘은 가능한 한 Unity 오브젝트에 직접 의존하지 않는 순수 C# 코드로 작성한다. 이를 통해 자동 테스트와 성능 측정을 쉽게 하고, 화면 프레임 속도가 계산 결과에 영향을 주지 않도록 한다.

## 12. 검증 기준

### 12.1 기능 검증

- 같은 시드와 설정에서 같은 지도가 생성되는가
- A*가 장애물이 없는 단순 지도에서 최단 경로를 찾는가
- 정점 충돌과 간선 충돌을 정확히 구분하는가
- Cooperative A*의 예약표가 시간별 점유를 올바르게 차단하는가
- CBS가 제약을 올바른 에이전트와 시간에 적용하는가
- 저장한 실험을 동일하게 다시 실행할 수 있는가

### 12.2 비교의 공정성

- 모든 알고리즘에 같은 지도와 배치를 사용하는가
- 준비 시간, 계산 시간과 화면 재생 시간을 구분하는가
- 알고리즘별 시간 제한과 실패 기준이 동일한가
- 여러 난수 시드를 반복하여 우연한 결과를 줄이는가
- 공개 모델과 직접 구현한 알고리즘의 출처와 조건을 명확히 기록하는가

### 12.3 연구 결과 표현

- 직접 실행하지 않은 실험을 수행한 것처럼 표현하지 않는다.
- 특정 논문에서 보고된 최대 성능을 모든 조건에 일반화하지 않는다.
- 학습 기반 AI와 수학적 휴리스틱을 구분한다.
- 새로운 방식의 성능은 기준 알고리즘 및 구성 요소 제거 실험과 비교한다.

## 14. 현재 확정 사항

- Unity와 C#을 사용한다.
- 화면은 2D 격자형으로 구현한다.
- 계산과 시각화를 분리한다.
- 노트북이 처리할 수 있는 범위에서 사용자 지정 규모를 지원한다.
- 판단용 AI는 우선 규칙 기반 적응형 방식으로 구현한다.
- 알고리즘 제작 도구는 선택식 기본 모드와 가중치 중심의 고급 설정으로 구성한다.
- PRIMAL은 공개 학습 모델의 추론 연동을 우선하며, 직접 학습은 선택 기능으로 둔다.
- 새로운 데이터 처리 방식의 구체적인 아이디어는 기존 알고리즘과 실험 기반이 완성된 뒤 설계한다.
