# CoMPaSS MAPF 연구 워크벤치

Unity **6000.4.0f1**, Windows용 2D 다중 에이전트 경로 탐색·비교 도구입니다. 지도 생성, 알고리즘 계산, 안전한 이동 실행, CBS 탐색 과정 재생, 연속 실험과 보고서 저장을 제공합니다.

전체 기능별 구현 상태, 수정 내역과 검증 근거는 [구현 기록](구현%20기록.md)에 정리했습니다.

## 시작하기

### Unity Editor

1. Unity Hub에서 **Add → Add project from disk**를 눌러 이 폴더(`CoMPaSS_UnityProject`)를 선택하고 `6000.4.0f1`로 엽니다.
2. 에셋 가져오기가 끝나면 `Assets/Scenes/SampleScene.unity`를 열고 **Play**를 누른 뒤 **Game** 탭을 확인합니다.
3. CoMPaSS 화면은 실행 시 자동으로 만들어집니다. 편집 상태의 Scene에 워크벤치 오브젝트를 배치할 필요가 없습니다.
4. Windows 실행 파일이 필요하면 상단 **CoMPaSS → Build Windows**를 사용합니다. 이 ZIP에는 미리 빌드된 Windows 실행 파일은 포함되어 있지 않습니다.

## 권장 사용 순서

워크벤치 위쪽 탭에서 필요한 화면으로 이동합니다. 화면 크기를 바꿔도 실험과 재생 상태는 유지됩니다.

1. **시작 · 프리셋**: 처음에는 충돌 예제, 다중 로봇 예제, CBS 예제 중 하나를 누릅니다.
2. **실험 설정**: 지도를 미리 보고 크기·장애물·시드·로봇 수·알고리즘을 조절합니다. 숫자는 Enter 또는 입력란 밖을 클릭하거나 다른 탭으로 이동할 때 적용됩니다.
3. **실행 · 리플레이**: 선택 알고리즘 실행을 누르고 재생·일시정지·한 단계·배속·선택 로봇 추적을 사용합니다. CBS 탐색 과정과 실제 이동 기록을 전환해 볼 수 있습니다.
4. **결과**: 요약·충돌·복구 로그를 확인하고 PNG, SVG, CSV, JSON, HTML/Markdown 보고서를 저장합니다.
5. **사용법**: 화면 조작과 각 알고리즘의 차이를 확인합니다.

실험 화면의 고정된 실행 버튼은 설정 목록을 스크롤해도 계속 보입니다. 작은 창에서는 설정과 미리보기가 위아래로 배치되고 각 목록은 자체 스크롤을 사용합니다. 지도 그림은 2560px PNG와 확대해도 선명한 SVG로 저장됩니다.

### 화면 조작

| 조작 | 기능 |
|---|---|
| 에이전트 마커 클릭 / 좌우 선택 버튼 | 에이전트 선택 |
| 선택 에이전트 따라가기 | 해당 에이전트를 중심으로 지도 표시 |
| 마우스 휠 / 확대 슬라이더 | 지도 확대·축소 |
| 우클릭 드래그 | 지도 이동 |
| 전체 지도 | 확대·이동·추적 초기화 |
| 장애물·시작점·목표점 도구 + 지도 클릭 | 실행 전 시나리오 편집 |
| 1× / 10× / 100× | 재생 배속 변경 |
| 예약표 / 새 제약 / 충돌 누적 | 관련 정보 겹쳐 보기 |

설정, 현재 상태, 결과는 각각 스크롤됩니다. 에이전트가 많아져도 전체 목록 때문에 지도 높이가 줄어들지 않습니다. 작은 화면에서 자세한 로그는 해당 패널을 스크롤해 읽습니다.

## 알고리즘과 충돌 처리

- **독립 A***: 각 경로의 최단 거리를 계산하는 기준선입니다. 에이전트 간 충돌은 별도로 기록됩니다.
- **Cooperative A***: 시간별 정점·간선 예약, 목표 도착 후 점유, 고정 또는 규칙 기반 우선순위를 사용합니다.
- **CBS**: 충돌 → 두 제약 분기 → 영향받은 에이전트 재탐색 과정을 기록합니다. 기본·DG·WDG를 선택합니다.
- **PRIMAL**: [공개 모델 연결 안내](Tools/Primal/README.md)를 따릅니다. 어댑터는 제공하며, 학습 모델과 TF 1.x 환경은 별도로 준비해야 합니다. 이 PC에서 실제 학습 모델 추론은 검증하지 않았습니다.

실제 이동은 **다음 한 단계의 전체 공동 행동을 먼저 검사**합니다. 충돌·미계획 경로를 발견하면 전원 정지하고, 자동 복구가 켜져 있을 때 대안 경로를 계산·검증한 후 재개합니다. 목표에 도착한 에이전트는 끝까지 해당 칸을 점유합니다. 복구에 실패하거나 제한을 초과하면 실패 원인과 기록을 보존합니다.

독립 A*의 복구에는 Cooperative A* 안전 계층을 사용하며, 선택적으로 CBS 대체를 허용할 수 있습니다. **원래 계획 성공률**과 **복구를 포함한 실행 성공률**은 서로 다른 지표입니다. 복구 후 결과를 원래 알고리즘의 성능으로 섞어 해석하지 마세요.

## 연속 실험

`연속 실험 / 자동 복구 설정`에서 다음 조건을 입력합니다.

```text
지도 크기: 12x12,20x20,32x32
에이전트 수: 4,8,16,32
장애물 밀도: 0.1,0.2,0.3
조건별 반복: 3
```

선택한 알고리즘과 설정은 고정되고 조건 조합·반복별 시드를 바꾸어 자동 진행합니다. 병목/좁은 통로에서는 병목 수·폭 목록도 사용할 수 있습니다. 지도 유형과 시작·목표 분포는 캠페인마다 선택합니다.

- 중지는 현재 계산을 취소하고 완료된 사례의 체크포인트를 남깁니다.
- `최근 연속 실험 이어하기`는 미완료 사례부터 다시 계산합니다.
- `results.csv`는 원시 결과, `summary.csv`는 같은 조건별 평균·분산·표준편차·범위·P95·실패 수입니다.
- 경로 비용·대기·완료 단계 통계에는 성공한 실행만 포함하며, 실패는 별도로 집계합니다.
- 100배에서도 논리 시간 단계를 건너뛰지 않습니다. 계산이 무거운 경우 실제 처리 속도가 100배에 도달하지 않을 수 있습니다.

## 연구 설정과 보고서

고급 설정에서 휴리스틱, 가중치, 이웃 탐색 순서, 동률 처리, 대기 허용, 우선순위 요소별 가중치와 계산 제한을 조절합니다. 프로필 저장·불러오기와 고정 순서/전체 가중치/요소 제거 비교를 지원합니다.

보고서 패널은 다음을 제공합니다.

- 화면 2배 PNG와 화면 해상도와 독립적인 지도 PNG/SVG
- CBS 제약 적용 전후 / 충돌 복구 전후 / 알고리즘 비교 PNG·SVG
- 이미지 메모·캡션, 최근 이미지 목록, Windows 이미지 클립보드 복사
- HTML·Markdown·CSV·JSON·차트를 포함하는 보고서 폴더
- 원래 계획과 실제 이동 기록의 분리 저장·불러오기

일반 데이터 경로는 `Application.persistentDataPath/CoMPaSS`입니다. 보고서의 `저장 폴더 열기`로 접근할 수 있습니다. Unity Player Settings의 회사명·제품명에 따라 상위 경로가 달라집니다. 진단 실행은 별도 검증 폴더에만 저장합니다.

## 예제·검증

- [예제 안내](Samples/README.md): 두 에이전트 충돌, 병목 지도, 32명 무작위 지도, 프로필, 실제 측정한 작은 비교 CSV
- `Tools/validate_core.py`: 설치된 .NET SDK로 순수 C# 회귀 검사 실행
- `Tools/validate_unity_compile.py <Unity 프로젝트 경로>`: 해당 Unity의 참조 어셈블리로 소스 컴파일
- 플레이어 인수 `--compass-verify <별도 출력 폴더>`: 충돌 복구·PNG/SVG 저장·소형 화면·연속 실험 중단/재개를 자동 점검하고 종료

검증 결과와 실행하지 않은 항목은 [구현 기록](구현%20기록.md)의 검증 절을 확인하세요.

## 현재 범위와 측정 해석

- 지도 한 변 4–64, 에이전트 1–32, 계획 시간 창 1–1024단계, 연속 실험 최대 2,000개 조건 조합을 지원합니다.
- CBS는 시간·노드·시간 창 제한 안에서 탐색합니다. 제한으로 중단한 사례를 해가 없는 문제라고 단정하지 않습니다.
- DG/WDG 보조 탐색이 제한에 걸리면 해당 쌍의 기여를 0으로, 정점 덮개 탐색이 제한에 걸리면 매칭 하한으로 낮춥니다. 적용 내역은 로그에 남습니다.
- A*/Cooperative 휴리스틱 가중치가 1을 초과하면 최단 경로를 보장하지 않습니다. CBS는 가중치 1·맨해튼·대기 허용을 유지합니다.
- 메모리는 프로세스 전체 관리 힙의 20ms 간격 표본입니다. 알고리즘 전용 최대 메모리나 GPU·Python 메모리를 뜻하지 않습니다.
- 지도 생성·화면 재생과 계획 시간을 분리합니다. 하드웨어, 실행 환경, 부하와 시간 제한에 따라 성능·제한 도달 시점은 달라집니다.
- Jobs/Burst는 적용하지 않았습니다. 이번 검증 빌드는 `--burst-disable-compilation`으로 수행했습니다. Editor에서 이전 Burst DLL 로딩 오류가 계속되면 **Jobs → Burst → Enable Compilation**을 해제한 뒤 사용할 수 있습니다. Windows 보안 설정은 변경하지 않았습니다.

## 2026-09-30 UI 업데이트

워크벤치는 **시작·프리셋 / 실험 설정 / 실행·리플레이 / 결과 / 사용법** 다섯 탭으로 정리했습니다. 예제를 고르면 설정으로 이동하고, 실행을 누르면 리플레이 화면으로 전환합니다. 탭을 바꿔도 진행 중인 실행과 리플레이 단계는 유지됩니다.

차콜 그레이와 회색 표면을 중심으로 색상을 정리하고, DPI·창 높이에 따라 글자 크기를 조정합니다. 화면 전체를 하나의 변환 행렬로 축소하지 않아 작은 창에서 글자가 지나치게 줄어드는 현상을 줄였습니다. 설정은 내부 스크롤로, 실행 버튼은 패널 하단에 고정됩니다. 결과 탭에서 기존 2560px PNG·SVG 및 보고서 내보내기를 사용할 수 있습니다.

이번 UI 코드의 Unity 편집기 컴파일과 플레이 화면은 이 기록을 작성할 때 별도로 확인하지 않았습니다.
